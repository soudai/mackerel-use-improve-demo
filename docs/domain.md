# 業務仕様とデモデータ

このリポジトリの main は改善前の基準実装です。性能上の問題と複雑な条件分岐を含みます。修正は別ブランチで一つずつ行います。

## 金額と価格計算

全金額は整数の `*_cents` で管理します。UI は cents を100で割って表示します。
`POST /api/quotes` と `PricingService::calculate(array $input)` の規則は同一です。

| 入力 | 範囲・初期値 |
| --- | --- |
| `unit_price_cents` | 1〜1,000,000 |
| `quantity` | 1〜100 |
| `customer_tier` | `regular` / `silver` / `gold` |
| `coupon` | null / `SAVE10` / `FREESHIP` |
| `region` | `tokyo` / `osaka` / `remote` |
| `express` | boolean、未指定は false |

1. 小計 = 単価 × 数量。
2. 会員割引は小計に対して計算し、端数を切り捨てます。

| 会員 | 数量 | 割引率 |
| --- | --- | --- |
| regular | 20以上 / それ未満 | 5% / 0% |
| silver | 10以上 / 5〜9 / 1〜4 | 10% / 7% / 5% |
| gold | 10以上 / 5〜9 / 1〜4 | 15% / 12% / 10% |

3. `SAVE10` は**割引前小計**が3,000以上なら、会員割引後金額の10%を追加割引します。端数切り捨て、上限2,000。
4. 送料判定の金額は、会員割引とクーポン割引を引いた後の金額です。
5. 通常地域（tokyo/osaka）の送料は600。割引後10,000以上または `FREESHIP` なら0。速達は最後に400加算。
6. remote の送料は1,200。割引後10,000以上なら600。`FREESHIP` は適用されません。速達は最後に800加算。
7. 合計 = 小計 − 会員割引 − クーポン割引 + 送料。

例：単価1,000、数量10、gold、SAVE10、tokyo、通常配送 → 小計10,000、会員割引1,500、クーポン850、送料600、合計8,250。

## 購入・在庫

`POST /api/checkout` は登録済みの顧客・有効な商品・数量1〜100を受け付けます。
在庫のロック、在庫確認、在庫減算、注文と明細の作成は一つのDBトランザクションで行います。
送料は配送モック `/quote` の整数 `shipping_cents` を使用します。合計は商品単価×数量+送料です。見積り用の会員・クーポン規則は、この単品購入APIには適用しません。
送料APIが失敗した場合、在庫減算と注文作成はロールバックされます。エラー応答した購入を自動再送する負荷生成は行わず、ロック改善後も在庫数・作成注文数の整合性を確認します。

基準実装は、在庫ロックを取得してから外部の送料APIを待ちます。人気商品の同時購入がロック待ちの再現条件です。改善PRでは、在庫不足・同時購入・送料API失敗時の挙動を保持してください。

## 一覧・検索・売上

- 注文一覧は id 降順、limit は1〜100（既定50）。顧客名を含みます。基準実装は注文ごとに顧客を遅延読込します。
- 注文検索は状態・作成日（UTC、両端を含む）で絞り、created_at 降順・id 降順。limit は1〜200（既定50）。既定は paid、2026-01-01〜2026-01-02。状態・日時に合う複合インデックスがなく、日時列に日付変換を適用する基準実装です。
- 売上レポートは paid 注文だけを含み、UTCの日付範囲を両端含みで集計します。既定は2026-01-01〜2026-01-31。gross_cents は明細の数量×単価で、送料を含みません。注文数は一意な注文ID数、数量は明細の数量合計、by_date は日付順の売上金額です。
- `orders_legacy_reference_idx` は廃止した検索機能の残存インデックスです。現在のAPIはこの列で検索しません。短時間の利用0回だけで削除を判断せず、用途・制約・観測期間を確認するデモに使います。

## Seed

`DemoSeeder` は固定乱数seed 20260101、UTCの2026年1月のデータを生成します。
顧客・商品は各1,000件、注文は `DEMO_SEED_ORDERS`（既定20,000、100〜1,000,000）、明細は注文につき3行です。人気商品ID 1の初期在庫は100,000です。
既に商品があれば再投入をスキップし、既存の業務データを削除しません。比較には同じ seed件数・初期在庫を使い、負荷で作成した注文を含む状態と初期状態を混ぜないでください。
